# QLCoder Data Repository

The `/data` directory contains the evaluation results from the paper **[QLCoder: A Query Synthesizer For Static Analysis of Security Vulnerabilities](https://arxiv.org/abs/2511.08462)**. 

## Files Overview

### Main Results
* [**`QLCoder.csv`**](QLCoder.csv): Experimental results cited in the paper.

### Ablations
To evaluate the impact of different system components, an ablation study was conducted on a [shared set of 20 CVEs](#ablation-cves).
* [**`QLCoder-NoAST.csv`**](ablations/QLCoder-NoAST.csv): QLCoder running without Abstract Syntax Tree (AST) input guidance.
* [**`QLCoder-NoDocs.csv`**](ablations/QLCoder-NoDocs.csv): QLCoder running without CodeQL documentation and example queries.
* [**`QLCoder-NoLSP.csv`**](ablations/QLCoder-NoLSP.csv): QLCoder running without the CodeQL Language Server Protocol (LSP) server.
* [**`ClaudeCode.csv`**](ablations/ClaudeCode.csv): Baseline results using the Claude Code agent without the QLCoder framework.

### Alternative Systems
Comparative evaluations against existing static analysis tools, evaluated on a shared set of 130 CVEs.
* [**`CodeQL.csv`**](CodeQL.csv): Baseline results generated using [default CodeQL queries](https://docs.github.com/en/code-security/reference/code-scanning/codeql/codeql-queries/java-kotlin-built-in-queries).
* [**`IRIS.csv`**](IRIS.csv): Results generated using the **[IRIS](https://arxiv.org/abs/2405.17238)** system.

### Cross-Model Comparisons
Evaluations of QLCoder powered by various LLMs, as well as each LLM without the framework, evaluated on a [shared set of 20 CVEs](#alternative-system-comparison-cves) (Note: these overlap with the ablation CVEs).
* [**`Gemini-2.5-Flash-qlcoder.csv`**](cross-model/Gemini-2.5-Flash-qlcoder.csv): Baseline results generated by Gemini 2.5 Flash with the QLCoder framework.
* [**`Gemini-2.5-Pro-qlcoder.csv`**](cross-model/Gemini-2.5-Pro-qlcoder.csv): Baseline results generated by Gemini 2.5 Pro with the QLCoder framework.
* [**`Codex-5-minimal-qlcoder.csv`**](cross-model/Codex-5-minimal-qlcoder.csv): Baseline results generated by Codex with GPT-5 minimal thinking with the QLCoder framework.
* [**`Codex-5-medium-qlcoder.csv`**](cross-model/Codex-5-medium-qlcoder.csv): Baseline results generated by Codex with GPT-5 medium thinking with the QLCoder framework.
* [**`Codex-gpt-oss-qlcoder.csv`**](cross-model/Codex-gpt-oss-qlcoder.csv): Baseline results generated by Codex with gpt-oss:20b with the QLCoder framework.
* [**`Gemini-2.5-Flash-no-qlcoder.csv`**](cross-model/Gemini-2.5-Flash-no-qlcoder.csv): Baseline results generated by Gemini 2.5 Flash with the QLCoder framework.
* [**`Gemini-2.5-Pro-no-qlcoder.csv`**](cross-model/Gemini-2.5-Pro-no-qlcoder.csv): Baseline results generated by Gemini 2.5 Pro without the QLCoder framework.
* [**`Codex-5-minimal-no-qlcoder.csv`**](cross-model/Codex-5-minimal-no-qlcoder.csv): Baseline results generated by Codex with GPT-5 minimal thinking without the QLCoder framework.
* [**`Codex-5-medium-no-qlcoder.csv`**](cross-model/Codex-5-medium-no-qlcoder.csv): Baseline results generated by Codex with GPT-5 medium thinking without the QLCoder framework.
* [**`Codex-gpt-oss-no-qlcoder.csv`**](cross-model/Codex-gpt-oss-no-qlcoder.csv): Baseline results generated by Codex with gpt-oss:20b without the QLCoder framework.

## Common Headings

The CSV files utilize several column headers to track query performance. 

> **Note on terminology:** 
> * **Results (`*_results`)**: The number of distinct vulnerability alerts found by CodeQL (reported in standard SARIF format).
> * **Paths (`*_paths`)**: The sum of the underlying codeflows comprising each result.

### Vulnerable Version Metrics (`vuln_*`)
These metrics evaluate the query's ability to successfully detect the vulnerability on the unpatched codebase.
* `vuln_num_results`: Total number of alerts (SARIF results) flagged by the query.
* `vuln_num_paths`: Total number of codeflow paths generated across all results.
* `vuln_recall_file`: File-level recall (whether the query successfully flagged the vulnerable file).
* `vuln_recall_method`: Method-level recall (whether the query successfully flagged the vulnerable method).
* `vuln_tp_results_file`: Number of true positive results that correctly intersect the vulnerable file.
* `vuln_tp_paths_file`: Number of true positive codeflows intersecting the vulnerable file.
* `vuln_tp_results_method`: Number of true positive results that correctly intersect the vulnerable method.
* `vuln_tp_paths_method`: Number of true positive codeflows intersecting the vulnerable method.

### Fixed Version Metrics (`fixed_*`)
These metrics evaluate the query's behavior when executed on the patched snapshot. A precise query should not flag the fixed version.
* `fixed_num_results`: Total number of alerts (SARIF results) flagged by the query on the fixed code.
* `fixed_num_paths`: Total number of codeflow paths generated on the fixed code.
* `fixed_recall_file`: File-level recall on the fixed version.
* `fixed_recall_method`: Method-level recall on the fixed version.
* `fixed_tp_results_file`: Number of alerts that intersect the patched file locations.
* `fixed_tp_paths_file`: Number of codeflows that intersect the patched file locations.
* `fixed_tp_results_method`: Number of alerts that intersect the patched method locations.
* `fixed_tp_paths_method`: Number of codeflows that intersect the patched method locations.
